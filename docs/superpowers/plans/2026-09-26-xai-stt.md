# xAI Speech-to-Text implementation plan

> Controller-direct execution with executing-plans and causal TDD; no subagents.

## Approved design and scope
Carlos supplied the xAI credential and asked “Essa é a chave api, deixe tudo configurado”, following the presented URL → bounded server download → REST xAI STT → same Maya design. Configure and qualify STT, then publish a retained-state CLOSED TEST successor. No GA/ManyChat opening, channel sends, financial effects, V3 or legacy changes. The provided key is outside Git in the deployment secrets directory; never put its value in docs/tests/logs/model context.

Architecture: extend the existing attachment reader, not a new agent or ingress. xAI returns literal speech text; Maya alone interprets it. Use POST https://api.x.ai/v1/stt, multipart options before file, pinned grok-voice-transcribe-2.0, format=false and language detection. Support documented audio container MIME types and bounded octet-stream signature recognition. Keep 4 MiB media bound and bounded transcript bytes, unavailable status on transport/empty/malformed/over-limit results. No silent clipping or semantic rewrite.

A disk cache bound to audio SHA/model avoids retranscription after failed turns/restart. An event/URL-bound successful attachment index supports re-extraction and dialogue history without a GET on replay. Commit original channel text plus explicitly labelled transcript to existing dialogue storage; source event hashing remains unchanged. No active SQLite edits or schema migration.
